# DSCT reasoning method — keep this reference

Use this structure whenever you need to make a claim inspectable. It is a
working habit, not a new point system.

| Part | Ask yourself |
|---|---|
| **Sources** | What definition, reading, data, example, or tool did I use? |
| **Rules / Assumptions** | What is already known? What am I assuming? What constraints apply? |
| **Work** | What reasoning, calculation, code, diagram, or test can another person inspect? |
| **Check** | What could be wrong? What test, second example, edge case, or comparison challenges my answer? |
| **One-Sentence Summary** | What did I conclude, and how did I reach it? |

When stuck, also write **Expected / Actual / Tried**:

- **Expected:** what I thought would happen.
- **Actual:** what happened, including the exact output or evidence.
- **Tried:** what I changed or checked already.

A good help request includes both the evidence structure and this short
history. “It does not work” is a starting feeling; it is not yet inspectable
evidence.
