Crack the shift cipher.

The activity uses A=0 … Z=25 and E(x) = x + k (mod 26). This page attacks that exact system, so you can test the claim “it’s secure because nobody knows my key.”

1 · Predict first the rule, from the activity

Encryption: E(x) = x + k (mod 26). Decryption: D(y) = y − k (mod 26). The keys are k = 0, 1, …, 25.

You have a ciphertext and no key. What is the most keys you would ever need to try?

26. That is every key there is (k = 0 does nothing, so 25 keys really change the text). Keep that number in mind while you read the next section.

3 · The activity's question from the activity

“This cipher is secure because nobody knows my key.” Name two assumptions hidden in that claim, including one about what an adversary can observe or try.

Write your own answer first. Then compare it with what the attack above needed:

  • The attacker could try every key. Only 26 exist, so “nobody knows it” quickly becomes “nobody has bothered yet.” The worst-case work grows with the size of the keyspace: with N possible keys, N tries. (Compare Week 6: that is linear in N.)
  • The attacker knows the method. The attack only worked because we knew the cipher was a shift by k. The claim quietly assumes the rule is also secret, and nothing in “nobody knows my key” says so.
  • The attacker can see the ciphertext, and can tell when they've succeeded. Try the random-looking preset with the word-flagging box on and off: when no row looks like anything, you cannot tell which key was “right.” Recognizing success is an ingredient of the attack, and part of the attacker model.

This is only about this one small system. It is not advice about how real-world security works.

4 · Optional: why the gcd question matters extension

The activity asks for 53 (mod 12), −5 (mod 12), and gcd(35, 26). Do those by hand first.

  • 53 = 4·12 + 5, so 53 ≡ 5 (mod 12).
  • −5 + 12 = 7, so −5 ≡ 7 (mod 12). The remainder is taken to be non-negative.
  • gcd(35, 26) = 1 (35 = 5·7, 26 = 2·13, no shared prime). Because the gcd is 1, 35 has an inverse mod 26: 35 ≡ 9, and 9 · 3 = 27 ≡ 1, so multiplying by 3 undoes multiplying by 35.
